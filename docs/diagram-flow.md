## 9段の流れ

各段の「こちら」は推奨案。A〜C の判断で差し替わる行には印を付けた。

### 1. 最初にまとめ

| 日報サイト | こちら（推奨） |
|---|---|
| 日報を書くこと自体が目的ではない | 答えを出すこと自体が目的ではない |
| 毎日の仕事を、成長の記録に変えるツール | **A** 何に対するもやもやかなのかを、自分で決める場所 |
| 見習いが振り返る → 上司が見る → AIが整える → 次で実践 | 書く → 一度返す → 本人が相手を選ぶ → 相手役と話す → 手放す |
| 一直線ではなく、毎日まわる循環 | 一直線の解決ではない。残して積み上げる循環でもない |

補足: 「誰にも届かない・残らない」はここには畳まない。2 と 7 で見せる。

HTML側のわかりやすさ:

- 一言は「何に対するもやもやかなのかを、自分で決める場所」。ヒーローに「対象」は出さない
- ヒーロー順: 名前 →「答えを出すこと自体が目的ではない」→ 一言 → 流れの帯（一言の直後が帯）
- リード（対象の注釈）は置かない。一言の次は流れの帯（日報サイトと同じ）
- 「人／期待」は図解に書かない。08-12の「自分の期待」は、相手への願いではなく自分のなかの見込み。公開実例（同僚＋課長）もそこまでは示さない
- 流れの帯のあとに、画面名を一度だけ対応させる（一度返す＋本人が選ぶ＝リフレクト。相手役と話す＝ステージ。消える＝手放す）。対応は既存の `.reduce` リスト。色・フォントは増やさない
- 「聞こえた人」は初出で「書いた文から浮かんだ人」と添える
- 「相手役」は初出で、実在のその人ではない・視点から話しそうな声、と添える
- 流れの文言をリード文で繰り返さない（帯が図）
- 3の対比行は「起きること／何の話か／本人側」。内部の「対象」は図解に出さない

### 2. 作ったもの（画面・中身・URL）

公開: https://reflective-ai-red.vercel.app

| 画面 | 中身（図解に出すこと） |
|---|---|
| 入口 | 「ここは、答えを出さない場所です。」誘い。「話してみる」。筋書きは出さない |
| 書く | AIは無言。うまくまとめなくてよい。保存されない、と書く |
| リフレクト | 聞こえた人を並べる。候補は「押してほしいボタン」の見た目にしない。本人が選ぶ。「もう少し続ける」は書く画面に戻る |
| ステージ | 選んだ相手役と話す。4往復か沈黙で「今のやり取りを、少し離れたところから返してもらいませんか」 |
| 終了 | 内容は保存されていない。話すことは、手放すこと。また書きたくなったら来てください |

日報サイトと同じく、画面モックを置く。流れは横並び（入口→書く→リフレクト→ステージ→終了）。その下にスマホ枠で「書く」と「リフレクト」（説明用。本文は架空の短文。ステージは出さない）。候補は薄い紺、終了系は灰色。URLはモックの下。

### 3. 解決したかった点／やりたかったこと（対比）

出発点（講座の「自分の困りごと」に対応。図解3の冒頭に置く）:

仕事の現場で聞いた声 — 辞めたい、雰囲気が悪い、コミュニケーションが取れていない、家庭のトラブルで辞めていく、離職を食い止めたい、外部カウンセラーに入ってもらいたい。  
作るのは離職対策や人の代わりではない。**社内では言いにくいことが、会社に届かない場所で言葉になる**場。答えも台本も出さない。EAP・産業医の断りは、相談アプリの一文に一度だけ置く。

そのあと、山場として ChatGPT。ほかは「これも見た」で止める。導入は「ちょっと違う」ではなく、ChatGPTは間違えていない・差は場の設定（誰が／いつ／何を／どう／誰に）を誰が決めるか。対比の各行に「起きること／何の話か／本人側」を付ける（内部メモの「対象」は図解に出さない。ヒーローで止めた語を、対比で復活させない）。図解の文面（3）: 差は、誰が／いつ／何を／どう／誰に、という場の設定を誰が決めるか、です。

| | BEFORE（ChatGPT） | AFTER（Reflective AI） |
|---|---|---|
| 起きること | 気持ちの相談を、解決すべき課題として受け取る | 答えも台本も出さない |
| 何の話か | AIが先に決める | 聞こえた人を並べ、本人が選ぶ |
| 本人側 | 考えが追い付く前に、出口が来る | 場の設定を、本人が決める |

**C** ここに 08-15 の要約を置くか、型だけにするか。

置く場合の実例（評価者向け1本。公開図解では職場に置き換える。元の比較メモは家庭の話のまま残してよい）:

- 入力: 同僚の言葉遣い。私にだけ命令口調。課長の前では少し和らぐ。言い方を変えてほしい
- ChatGPT: 共感のあと、台詞と次の作業
- 本人: どんどん提案してくれるけれど、考えが追い付かなくなる…
- Reflective AI: 同僚と課長を並べ、本人が選ぶ。普段言えないことが出た。抑圧や「傷つけちゃうな」に自分で気づいた（図解の心の声: 私、抑圧されていたんだ…、本当にこんなことを言ったら傷つけちゃうな…）

さりげなく（表にしない。固有名を並べて競合比較しない）:

相談アプリ（書いて分析し、記録が残るもの）も見た。第三者を介して相手に届ける組織の手法や、自分を感じ取ってから人と話す手法も見た（アシミレーション、レゾナント・コミュニケーションの名は図解に出さない。型だけ）。こちらは誰にも届けない。判断せず、残さない。機能が少ないのではなく、思想が逆。EAP（会社が用意する外部の相談窓口）や産業医の代わりでもない。出発点の箱では EAP を重ねない。

### 4. 作りたかった理由／自分への問い

日報サイトの「毎日、自分に問う4つのこと」に相当する段。利用者に出さない評価者用の言葉で書く。

気持ちの相談では、本人にもまだ決まっていないことが多い。

1. 何に対するもやもやか（対象）。図解の見出しはこのまま。「人／期待」は書かない。説明は「まだ本人にも決まっていない。答えが出ると、先に決まってしまう」（②と揃えるため。空にしない）
2. そのときの自分の気持ち（客観視）。説明は「外から見ること。まだ本人にも、言葉になっていないことが多い」

どちらも本人にしかできない。答えないのは優しさではなく、このふたつを本人に残すため。図解の文面も同じ（「この工程」は使わない）。
3の「場の設定」（誰が／いつ／何を／どう／誰に）と同じ思想。4のふたつは5Wの言い換えではない（②は客観視）。だから4の見出しに5Wは繰り返さない。

書かない: 「準備ツール」。書かない: 理念語（自分で決める力）を見出しにすること。

#### ② 知覚の理論との対応（`docs/perception-science-grounding.md`）

証明ではなく、構造のアナロジー。図解では対応表を小さく置く。効能の根拠にはしない。  
図解の一文（表の直前）: 下の表は、理論の名前を借りて、同じような仕組みの形を説明しています。アプリの効能の根拠にはしません。

| 理論 | 要点 | このツールでの対応 |
|---|---|---|
| 構成的知覚（ヘルムホルツ、グレゴリー） | 見え方は、外から与えられるのではなく、本人の枠組みで構成される | 状況（事実）は変えない。別の視点を並べ、切り替えるかは本人 |
| 多義図形（ネッカーの立方体、ルビンの壺） | 刺激は同じなのに、解釈だけが入れ替わる | 同じ一文から、同僚と課長のように複数の人が聞こえる。何の話かをAIが一つに決めない |
| ゲシュタルト（洞察） | 断片が、まとまりとして見え直したときに腑に落ちる | 書く＝断片を外に出す。リフレクト＝一度返して、外から見る |
| ベイズ脳／予測処理 | 更新するのは常に本人の内部モデル。外から答えを注入しない | 診断・結論を渡さない。返して止まる |
| アフォーダンス（補助） | 行為の可能性は、すでに本人の側にある | 決める工程を本人に残す。AIが代わりに出口を渡さない |

図解に書く一言: 出来事、そこであったことは変わりません。変わるのは見え方です。どの見え方で見るかは、自分で選びます。

### 5. ツールを使った未来 **B**

日報サイトは「成長して、また仕事へ。まわるほど積み上がる」。こちらはそれを真似しない。

| 書く | 書かない |
|---|---|
| 終了したら消える。残らないこと自体が、本音を書ける条件。できないから残さないのではない。預からない設計 | 成長が積み上がる |
| また書きたくなったら、いつでも来てください（通知はしない） | 使い続けるとこうなります |
| 変化の話をするなら、6分原稿の「私に起きたこと」だけ | WHY-ja の仮説を未来として断言する |

6分原稿で使える実例（効能の約束にしない）: アプリを開いていないときに嫌な声かけを受け、なぜ嫌なのかまで自分で降りていけた。使うほど、AIなしでも自分で気づける方向。**それが、この場の向き**（皆さんもこうなる、とは言わない）。

### 6. AIの立場

日報サイト: AIは指導者ではない。翻訳者。内容を決めるのは上司。

こちら:

- AIは相談相手ではない。答えも台本も出さない
- リフレクター（一度だけ返す役）は、聞いたことを一度だけ返す。対話しない
- ステージの相手役は、視点を推測して声を担う。本人の代わりにその人になるのではない
- 誰と話すかは、AIが決めない
- 返す文を書くこと自体は、汎用AIにもできる。できないのは、**返して止まること**

#### ③ 例外 — 危険信号（`docs/crisis-safety.md`）

中心にはしない。6のあとに短く。入口には窓口を並べない（場が治療の待合室になる）。

- 結論を出さないのは、自分で決める力が前提だから。その力が一時的に働きにくいときだけ、例外にする
- 例外を担うのはリフレクターではない。**場**（画面に差し込む案内。AIの返答ではなく、こちらが用意した文）
- L2: 流れは続ける。窓口を小さく、静かに添える
- L3: 流れを止める。窓口を主にする。相手役は応えない。追い出さない
- 電話番号はモデルに書かせない。最新の一覧は厚労省「まもろうよ こころ」

### 7. 「しない」を貫く（減らすこと）

図解のeyebrowは「7 · 「しない」を貫く」。h2は「足すことではなく、減らすこと」。日報の「使いやすい工夫」は借りない。続けやすさの話ではない。

日報サイト: 日付自動、タップを減らす、毎日続けられる軽さ。

こちらが減らしているもの（機能追加ではない）:

- 保存しない（一度終わったら、次に開いたときには残っていない）
- 通知・リマインドを入れない
- 候補を「押してほしいボタン」にしない（誘導しない）
- 「もう少し続ける」は、AIと会話することではない。書く画面に戻る
- 入口に筋書きも効能も置かない。場の約束だけ

### 8. 苦労した点

日報サイト: 機能を増やしすぎない。続けやすさ側に倒した。

こちら:

- 足したくなるもの（分析、記録、通知、AIとの対話、相手の自動決定）を、入れなかった
- 知人に使ってもらったところ、話す相手をAIが一人に決めていた。聞こえた人を並べ、本人が選ぶ形に直した
- もともとオープンダイアローグを知っていて、アプリにできないかと思っていた。現場で聞いた声が後押しになった。ただし、記録を残して積み重ねる対話（オープンダイアローグと呼ばれるやり方）そのものにはしなかった。残らない場のままにした

迷ったときは、「本人の工程が残るか」側に倒した。

### 9. 最後に

図解のeyebrowは「9 · 最後に」（1の「最初にまとめ」と対）。日報の「持ち帰ってほしいこと」は借りない。h2は「この図解で伝えたいこと」。

01. 課題は、気持ちの相談で、何の話かをAIが先に決めてしまうこと  
02. 中心は、書く → 一度返す → 本人が選ぶ → 相手役と話す → 手放す。一直線の解決ではない  
03. AIは返して止まる。設計の工夫は、足すことではなく、減らすこと  

締め（推奨）: 主人公は自分。何の話かも、誰と話すかも、自分が決める。AIは先に答えを出さない。

締めのあと（今後の一文）: いまは個人が、一人で開く場です。将来は、場を用意する側にも届けたい。判断しないという約束は、言葉が変わっても同じです。市場名（セミナー・企業・介護）は並べない。音声の機能予告は置かない。

## 知人に勧めるとき（ウイルス・古いiOS・社用PC）

図解の中心ではない。評価者図解には置かない。知人に渡すとき・商用の注意は口頭か別紙。心配の種類を分ける。

### 「ウイルス対策は大丈夫か」

心配しているのは、だいたい「怪しいものを入れると端末が壊れる」こと。このツールは、その経路ではない。

| 心配 | 答え |
|---|---|
| アプリを入れるのか | 入れない。ブラウザで開くページ |
| ファイルや実行ファイルを配るのか | 配らない。インストールもない |
| 怪しいサイトでは | 公開は Vercel の HTTPS。リポジトリも GitHub にある |
| 端末の写真・連絡先を取るのか | 取らない。アカウントも作らない |
| 書いたことは残るのか | ここには保存しない。終了したら消える |

隠さないこと: **書いた文は、応答をつくるためにAIへ送られる。** 画面にもそう書いてある。ウイルスの話と、中身が外に出る話は別。後者は「残らない場」の条件として、入口で先に伝えている。

「絶対安全」とは言わない。言えるのは、入れるアプリではなく、保存せず、アカウントを作らない、という設計であること。

### 「iOSが古いと開けない」

事実。ウイルスではない。使っている仕組み（Next.js 16）が、Safari 16.4 以降を前提にしている。おおよそ **iOS 16.4（2023年3月）より前** だと、ページが開かない・動かないことがある。

勧めるときは、iPhoneの「設定 → 一般 → 情報」のバージョンを見てもらう。足りなければ、更新できる端末か、別の端末。

### 「会社のPCだとセキュリティーに引っかかる？」

ありうる。ウイルス検査で落ちる、というより、**会社のネット制限**（未知のサイト、個人利用、AI系）で止まることが多い。自分の会社PCでは開けた。会社ごとにポリシーが違うので、夫の会社で止まることは別問題。

開けないときの逃げ道は、個人のスマホ（新しいiOS）か、自宅のPC。社用PCに入れて使う前提にはしない。

図解のURL近くに置くなら、一行で足りる: 入れるアプリではありません。古いiPhoneでは開かないことがあります。会社のネットでは止まることがあります。
