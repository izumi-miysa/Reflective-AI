# Reflective AI 壁打ちログ（2026-08-06・続き）

テーマ：危険信号（自傷・希死念慮など）の線引きと、専門support窓口への接続設計

---

## 1. なぜここだけ「例外」にするのか

- これまでの設計原則は「結論を言わない・指導しない・導かない」。
- これは、利用者が「自分で決める力」を持っているという前提の上に成り立つ。
- 希死念慮や自傷リスクが高い状態は、その「自分で決める力」自体が一時的に機能しづらくなっている状態と考えられる。
- → ここでの介入は理念からの逸脱ではなく、**理念（自分で決める力）を守るための例外的対応**として位置づける。
- 海外では、AIコンパニオンが自殺の具体的な方法を示唆した事例が報告され、運営会社の「検閲したくない」という姿勢が批判された。理念を字義通り徹底すると、命に関わる場面でも沈黙してしまう危険がある。

## 2. 3段階トリアージ設計

厚労省のSNS相談事業ガイドラインでも、危険度の高い単語を含む相談を優先対応するトリアージの仕組みが実践されている。これを参考に、Reflective AIも強度別に3段階で設計する。

### レベル1：平常時（壁打ちモード）
通常のリフレクティング。結論を出さず、一人称で映し返す。

### レベル2：注意信号（圧倒されている兆候）
- 消耗・絶望を示す言葉（「もう無理」「疲れた」「消えたい」）が、継続性を示す言葉（「ずっと」「毎日」「何ヶ月も」）と一緒に出てくる
- 自分の存在価値を否定する言葉（「いない方がいい」「迷惑をかけている」）
- 助けを拒否するようなニュアンス（「誰にも言わないで」「これ以上聞かないで」）

→ リフレクターの姿勢を保ちながら、さりげなく安全確認を挟む段階。結論を強制せず、専門窓口を押し付ける段階ではない。

### レベル3：危険信号（即時対応が必要）
- 具体的な手段への言及（方法・道具・場所など）
- 具体的な時期への言及（「今夜」「今から」「もう決めた」）
- 別れを示唆する言葉（持ち物の整理、遺言めいた発言、SNSでの発信予告）

→ 「結論を言わない」原則を一時的に手放し、断定的・明確に専門窓口の情報を提示する。

### 判定精度についての注意点
- 単語単体ではなく「組み合わせ」「文脈（レベル2が続いた末か、唐突か）」で見る
- 誤検知を恐れて閾値を上げすぎない。多少過敏でも拾う設計を優先する（命に関わる場面のため）
- 日常的な誇張表現（「忙しくて死にそう」等）を除外するフィルタは技術検証が必要

## 3. レベル2〜3で「壁打ちの信頼」を壊さない

- これまで大事にしてきた「評価しない」という信頼関係が、危険信号の場面で急に「マニュアル対応」に切り替わったと感じさせると逆効果になりうる。
- 窓口提示の際も、突き放すのではなく、それまでのリフレクターとしての一人称の言葉を保ったまま、窓口情報を"付け加える"形にする。
- レベル3対応は一度きりで終わらせず、その後の会話でも安全確認を自然に継続できる設計（会話の"覚え"）が必要。

## 4. 窓口の出し分け設計

対象者や状況に応じて、案内する窓口を変える。

| 対象・文脈 | 窓口例 | 備考 |
|---|---|---|
| 汎用（誰にでも出す1本目） | よりそいホットライン 0120-279-338 | 24時間対応、フリーダイヤル |
| 電話が苦手／若年層 | いのちの電話（メール相談）、SNS相談（こころのほっとチャット等） | テキストベースの選択肢 |
| 女性のエンパワメント文脈（DV・性被害等） | 女性支援団体の専門窓口（BOND project等） | 一般窓口より専門窓口の方がシェルター等の実支援につながりやすい |
| ハラスメント・職場関連 | みんなの人権110番（法務省）0570-003-110 | 平日8:30〜17:15 |
| 地域の公的機関につなぎたい場合 | 全国一斉こころの健康相談統一ダイヤル 0570-064-556 | 発信地域の公的相談機関に自動接続 |
| 24時間の電話相談（最終ライン） | いのちの電話（全国50カ所以上のネットワーク、通常10:00〜22:00・年中無休、匿名・無料） | 自殺対策強化月間等は時間拡大あり |

### 出し分けのロジック
- 利用者に属性を直接尋ねない（不自然、信頼を損なう）
- それまでの会話の文脈から自然に判断する
  - 職場の話が中心 → みんなの人権110番も併記
  - 家族・パートナーとの関係が話題 → 女性支援団体の窓口も併記
  - 文脈が読み取れない・一般的 → よりそいホットライン＋いのちの電話を基本セット
- 窓口は一度に並べすぎない（多すぎると選択の負荷になる）。基本は1〜2本に絞る

## 5. 実装上の注意点

- 窓口情報（電話番号・受付時間）はハードコードせず、更新可能な形で管理する（実際に受付時間が変更される例がある）
- リンク先は必ず公式サイトのみ参照する（偽サイトの報告例があるため）
- MVP段階では精緻な出し分けより、まず「よりそいホットライン＋いのちの電話」の基本2本を確実に出せることを優先し、出し分けは後続フェーズで精度を上げる

## 6. ドキュメントへの明文化（案）

README/Visionの「答えを与えないAI」という理念との整合性を保つため、以下のような一文を明記しておく：

> Reflective AIは、利用者の自分で決める力を尊重し、結論を提示しません。ただし、生命に関わる危険が示唆された場合に限り、専門機関への接続を明確に案内します。これは理念の例外ではなく、利用者の「自分で決める力」そのものを守るための対応です。
