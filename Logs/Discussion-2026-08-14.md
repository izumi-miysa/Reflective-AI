# Discussion 2026-08-14

知人テストで出た見た目・体験の指摘への対応。

---

## 1. 書く画面の文字が細くて小さい

指摘: 見出し（「今、気になっていることを…」）に比べて、自分が打った文字が細く小さく見づらい。

原因: `.writing-area` に `font-size` の指定がなく、body既定の16px・通常太さのままだった。見出しは最大30pxの太字なので、デスクトップで約1.9倍の差があった。

対応:

- `.writing-area` を 17px / 行間1.9 にした（スマホも17px。16px未満はiOSが自動ズームするため下げられない）
- 見出しの上限を 30px → 26px（スマホ 26px → 23px）に下げ、差を詰めた

書いた本人の言葉が主役なので、見出しを下げて本文を上げる方向で揃えた。

## 2. ステージの長文が読みにくい

指摘: 長文になったときに初めの方が見づらい。

原因は2つ重なっていた。

- 枠の高さがスマホで `min(38vh, 320px)` と低く、長い発言が数行しか見えない
- 新しい発言のたびに末尾の空要素へ自動スクロールしていたため、長い返事が来ると**冒頭が上へ流れた状態で止まる**

対応:

- 高さを スマホ `min(52vh, 420px)` / デスクトップ `min(56vh, 520px)` に広げた
- 自動スクロールの基準を末尾の空要素から「最後の発言そのもの」に変え、`block: "nearest"` にした。短い発言は従来どおり全体が見え、枠より長い発言は先頭が上に揃うので冒頭から読める

## 3. 「ほかの他人の意見を聞くの？ほかに伝わるの？」

指摘: Reflective AI に訊くとき、他人の意見を聞かれるのか、他に伝わるのか不安になった。

原因は説明の**場所が遅い**こと。相手役がAIだという説明は、ステージを開いた後のシステムメッセージにしか無かった。不安が生まれるのは書く時点で、そこには「保存されません」しかなく、**他人に伝わるかどうかに触れていなかった**。加えて提案ボタンが「〇〇さんに、少し声をかけてみますか」なので、本人に連絡が行くように読める。

対応:

- 書く画面の安心文を「判断やアドバイスはしません。書いたことは応答をつくるためにAIへ送られますが、保存されず、ほかの人に伝わることもありません。」に変更
- ステージを**開く前**（リフレクターの提案の時点）に「〇〇さんの声は、AIが視点を推測して演じます。実際のご本人に届くことはありません。」を追加

正確さの判断: 書いた内容は応答生成のため Anthropic の API へ送っている。だから「誰にも見られません」とは書けない。「AIへ送られるが、保存されず、ほかの人に伝わらない」という事実どおりの書き方にした。信頼を扱う製品なので、ここを曖昧にしない。

## 4. 敬称を「〜さん」に寄せる（2026-08-08 の決定を一部上書き）

指摘（Founderの実践に基づく）: 人がリフレクトするときは、「泉」でも「泉ちゃん」でも **「泉さん」** と呼ぶ。娘・息子も同様。ただし「お父さん」はそのまま、「義母」は「お義母さん」。

2026-08-08 では「人名の敬称は書かれた表記をそのまま使い、勝手に『さん』へ正規化しない」と決めていた。今回はリフレクターについてこれを上書きする。実践での語り方が根拠。同じ08-08の「誇張しない（1回しか出ていないのに繰り返しと言わない）」は別ルールとして残る。

### 変換を担う場所

プロンプトだけでは直らなかった。`anthropic.ts` が `alignPersonLabel` でモデルの「泉さん」を原文の「泉ちゃん」へ**戻していた**ため、逆補正を外す必要があった。

- `mock.ts`: `alignPersonLabel` を廃止し、`toReflectorLabel(label, kind)` を追加。続柄の対応表を持ち、決定的に変換する
- `prompts.ts`: 出力JSONに `personKind`（name / relation / role / unknown）を追加。人名と判定できないものに「さん」を付けて「仕事さん」のような事故を起こさないため
- `anthropic.ts`: `alignPersonLabel` → `toReflectorLabel`。プロンプトにも「文中の呼び方 → 使う呼び方」の対応を渡す
- 本文（message）の呼び方はプロンプトのルールで揃える。**引用（「」で本人の言葉をそのまま示す部分）は原文のまま**

### 対応表

| 入力 | 種別 | リフレクターの呼び方 |
|---|---|---|
| 泉 / 泉ちゃん / Nくん | 人名 | 泉さん / Nさん |
| すでに 泉さん・様・氏 | 人名 | そのまま |
| 娘 / 息子 | 続柄 | 娘さん / 息子さん |
| 義母 / 義父 | 続柄 | お義母さん / お義父さん |
| 母 / 父 | 続柄 | お母さん / お父さん |
| お父さん / お母さん | 続柄 | そのまま（二重敬称にしない） |
| 妻 / 夫 / パートナー | — | そのまま（本人の言い方を変えない） |
| 上司 / 部下 / 同僚 / 先輩 / 後輩 / 友人 | — | そのまま |
| 田中部長 | 役職 | そのまま |

兄・姉・弟・妹・子どもも続柄として同じ扱いにした（お兄さん／お姉さん／弟さん／妹さん／お子さん）。

### ステージ側は変えない

相手役の口調と第三人称は**原文どおり**を維持する。ステージは本人と相手役の距離感を保つ場なので、「泉ちゃん」と語りかける関係をこちらで丁寧語に直さない。「〜さん」ルールはリフレクター側だけ。

### 検証

mockモードで `/api/reflect` を叩き、7ケースを確認した。

泉ちゃん→泉さん / 娘→娘さん / 義母→お義母さん / お父さん→お父さん / Nくん→Nさん / 妻→妻 / 上司→上司。すべて期待どおり。

### 本人テストで出た不具合（同日、修正済み）

入力: 「夫の言葉遣いが気になっている。私が指摘しても聞き入れなかったが、娘の言葉は効いているようだ」

3つの症状が出た。

1. リフレクターが「ここに夫さんという方がいます」と言った
2. ボタンが「少し効いているように少し声をかけてみますか」になった
3. その上の文が「少し効いている様の声は、」になった

2と3の原因は `extractNameForms` の正規表現。`(さん|くん|ちゃん|君|さま|様|氏)` を敬称として拾うため、**「効いている様だ」の「様」を敬称と誤認**し、「少し効いている様」を人の呼び名として抽出していた。それがプロンプトに「文中の呼び方」として渡り、UIのラベルにもなっていた。この誤検出は今回の変更以前からあったが、呼び方をプロンプトに渡すようになって表面化した。

対応:

- 名前部分を「漢字・カタカナ・英字だけの6文字以内」に限定した。ひらがなを含む語（＝文の途中）は名前として拾わない
- 「神様」「皆さん」のような一般語を除外リストで弾く
- 「お母さん」のようにひらがなを含む続柄は、続柄側の対応表で拾えるので取りこぼさない

1の原因はプロンプト。「妻・夫はそのまま」と書いていたが守られなかったので、禁止例（「夫さん」「妻さん」「上司さん」とは言わない）を明示した。あわせて「〇〇という方がいます」のような紹介口調を禁止し、「〇〇のことが書かれていましたね」の形に寄せた。

UI側も、誤ったラベルが文章に混ざると不自然になるため、呼び名の差し込みを減らした。

- ステージを開くボタン: `〇〇に、少し声をかけてみますか` → **「少し話してみませんか」**
- その上の説明: 呼び名を差し込まず「相手役の声は、AIが視点を推測して演じます。実際のご本人に届くことはありません。」に固定

検証（mock 7ケース）: 夫の…効いている様だ → 夫 / 娘 → 娘さん / 田中さん → 田中さん / たくさん → その方 / 皆さん → その方 / 泉ちゃん → 泉さん / 義母 → お義母さん。

検証（Claude 実呼び出し）: 「夫の言葉遣いのこと、そして娘さんの言葉が届いているように見えること、書かれていましたね。」— 「夫」に「さん」が付かず、紹介口調も出なくなった。
